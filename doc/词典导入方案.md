# 单词书导入自动化方案 (Alibaba AI 版)

## 1. 背景与目标

目前红宝书等词书的导入过程（PDF -> SQL）过于手动化，且缺乏新词的关联资源（如例句、发音、高亮、排名等）。为了简化流程并支持长期的词库扩充，我们需要构建一个完整的系统管理功能，实现：

- **全自动化**：输入单词文本，一键产出带音标、释义、例句、发音、高亮的完整词库。
- **AI 赋能**：采用**阿里云 AI (通义千问 & CosyVoice)** 替代手动 Coze 流程。
- **自动同步**：生成的系统数据变更通过 `SysDbLog` 自动同步到老用户的本地数据库。
- **任务监控**：管理员可实时监控导入任务的进度。

## 2. 核心逻辑设计

### 2.1 任务管理 (Task Infrastructure)

- 后端增加 `ImportTask` 实体，记录任务状态（PENDING / RUNNING / COMPLETED / FAILED）、进度（已处理数/总数）、日志及配置。
- 采用异步处理（Spring `@Async` 或线程池），支持大规模单词列表导入。

### 2.2 阿里云 AI 接入

- **文本能力 (Qwen-Max/Plus)**：
  - 生成音标、释义、常用度排名、例句、例句翻译。
  - **核心点**：Prompt 中要求 AI 对英文例句和中文例句中的单词及对应释义进行 `<b>` 标签标注，方便前端直接渲染高亮。
- **音频能力 (CosyVoice)**：
  - 调用阿里云 TTS 生成例句 MP3。
  - 文件命名规则遵循现有的 `englishDigest` (MD5) 逻辑，存放在 `/var/www/html/sound/sentence/`。

### 2.3 释义使用策略 (Usage Mode) 

管理员在导入时指定：

- **专用释义 (Dedicated)**：新词书的每个单词仅使用此书提供的释义，存放在特定 `dict_id` 下，不进入通用词库。
- **非专用释义 (Common)**：释义忽略或作为通用词典的补充（存入 `dict_id='0'`）。对于系统中不存在的新词，优先考虑将其归属到特定词书以避免通用词库无限膨胀。

### 2.4 数据同步 (Synchronization)

- 导入流程在写入数据库（`MeaningItem`, `Sentence`, `WordSentence`）时，必须显式触发 `SysDbSyncBo.logOperation()`。
- 这样会递增系统版本号，App 客户端在下次同步时会自动收到增量更新并更新本地 SQLite。

## 3. 实现阶段

### 第一阶段：后端基础设施

- 创建 `ImportTask` 表及相关持久化逻辑。
- 接入阿里云 SDK (DashScope)。

### 第二阶段：导入引擎开发

- 实现 `DictImportService` 核心流水线。
- 逻辑：查词 -> AI 补足资源 -> TTS 发音 -> 写入库并生成日志。

### 第三阶段：管理后台 UI (Flutter)

- 创建 `AdminImportPage` 用于文本输入和参数设置。
- 创建 `TaskProgressPage` 用于实时进度查看。

## 4. 总结

本方案将红宝书等词书的“工程化导入”转化为“系统化管理”，极大地降低了内容维护成本，同时利用阿里云 AI 解决了高亮标注和高保真发音两项核心体验难题。
