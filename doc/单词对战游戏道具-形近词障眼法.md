# 单词对战游戏创意道具：形近词障眼法（Confusable Fog）

> 联动档案：[design/ideas.html](file:///Volumes/ssd/ppdc/design/ideas.html)（IDEA #002）

## 1. 创意背景与设计动机

### 1.1 现状与痛点
在目前的单词对战游戏（如俄罗斯方块对战 `russia`）中，核心机制是通过识别下落单词并从 4 个中文选项中快速选出正确释义：
- 目前服务端（`GetNextWordProcessor.java`）在出题时，错误选项是从当前游戏大厅词表中**随机抽取其他单词的释义**。
- **痛点**：随机抽取的干扰项通常语义相去甚远（例如题目是 `apple`，干扰项可能是 `destination`、`elephant`）。玩家往往不需要深度认知单词拼写，凭语感、大意或常识大类即可**瞬间用排除法秒选**，失去了单词辨析的深度与竞技张力。

### 1.2 创意核心思想
引入一种高阶进攻型策略道具——**「形近障眼法」（镜像迷雾 / Confusable Fog）**：
- **效果**：玩家对对手施放该道具后，使**对方在接下来的答题中，所有混淆干扰项全部来自于当前题干单词的「形近词（Confusable Words）」释义**！
- **效果演示**：
  - 题目单词：`adopt`（收养；采纳）
  - 常规干扰项（排除法秒过）：`大象`、`目的地`、`铅笔`
  - **形近障眼法生效下的干扰项**：
    - ① `适应；改编`（来自形近词 `adapt`）
    - ② `熟练的；内行`（来自形近词 `adept`）
    - ③ `熟练；精通`（来自同根/形近词 `adeptness`）
    - ④ 正确答案：`收养；采纳`
- **心理认知压制**：对手即便模糊认识 `ad*pt` 这个形态，面对一堆拼写差之毫厘的词义时，排除法彻底失效，必须精准调动记忆细节。稍一犹豫就会因方块下落而陷入心智慌乱，失误率与打乱节奏的效果极其显著。

## 2. 详细机制设计

### 2.1 道具获取与消耗
1. **触发契机**：
   - 现有机制作法：连对 5 题随机奖励 1 个道具（现有道具池为 `加一行(0)`、`减一行(1)`）。
   - 升级后：可将道具池扩展为 3 种，或通过特定竞技事件（如反超、精准连击）获得。
2. **使用限制**：
   - 即点即用，单次释放消耗 1 个道具。
   - 具有独立的道具标识与酷炫释放音效 / 迷雾微动效。

### 2.2 生效时长与作用域（奥卡姆剃刀与克制原则）
- **持续题数**：单次释放作用于对手接下来的 **2 ~ 3 道题目**（或限定 10 秒时间窗口内）。
- **对战平衡**：
  - 绝不搞永久致盲或不可解的惩罚；
  - 2~3 题的形近词高压足以打乱对手的手速心流，逼迫对手思考降速，达到战略牵制目的；
  - 结束后对方恢复常规混淆项。

### 2.3 混淆词匹配与降级策略（自洽无破绽）
为了保证题库出题的 100% 成功率与鲁棒性，出题引擎遵循以下三级漏斗算法：
1. **第一梯队（严格形近词）**：
   - 编辑距离（Levenshtein Distance）≤ 2，且长度差 ≤ 2（如 `altitude` vs `attitude`，`complement` vs `compliment`）。
2. **第二梯队（同前缀/同词根衍生词）**：
   - 若当前题库中编辑距离 ≤ 2 的词不足 2 个，自动扩充至公共前缀 ≥ 4 个字符的同词族词。
3. **第三梯队（兜底平滑降级）**：
   - 若该词极为生僻，词库中实在凑不齐形近词，则平滑补充高频词/普通随机词，确保选项始终为 4 个，绝不报错或阻塞游戏。

## 3. 技术实现与架构可行性分析

### 3.1 既有资产复用
本项目此前已在 `design/confusable_words_*` 以及 `WordBo` 中沉淀了高精度的形近词计算与聚簇排序体系：
- 拥有经过剪枝优化（长度分桶剪枝、编辑距离下界计算）的 Levenshtein 算法；
- 具备对词库词汇进行离线/预计算索引或内存预加载的能力。

### 3.2 服务端出题改造点
- **文件**：`server/nnbdc-service/src/main/java/beidanci/service/socket/system/game/russia/state/GetNextWordProcessor.java`
- **逻辑**：
  1. 在 `UserGameData` 中增加 `confusableDebuffRemaining: int`（剩余受影响题数）。
  2. 客户端触发道具后，向服务端发送指令 `useProp(PROP_CONFUSABLE_FOG)`。
  3. 服务端给对手打上 Debuff 标记，并广播双方播放对应动效/音效。
  4. 当对手请求 `getNextWord` 时，若 `confusableDebuffRemaining > 0`：
     - 调用形近词生成器：`room.getHall().getConfusableWords(word, count=2)`；
     - 取出其释义替代随机单词释义；
     - `confusableDebuffRemaining--`。

### 3.3 机器人（Bot）行为同步自洽
- 当对手是机器人且被施加该道具时：
  - 服务端可根据难度参数，将机器人的思考时间适当延长（模拟人类面对形近词时的犹豫辨析过程），或按比例小幅提升机器人的答错率（模拟形近词认知误导）。
- 机器人使用道具时：
  - 机器人也可根据战局（如落后、对手连对时）向人类玩家施放此道具，提升对战沉浸感与挑战趣味。

## 4. 总结与后续推进
- **用户价值**：将枯燥的被动背单词转变为高刺激、高沉浸的策略对抗，并在对抗中深刻记住最容易考错的形近词。
- **落地路线**：
  1. 第一阶段（当前）：完成玩法机制设计与设计档案归档。
  2. 第二阶段：服务端形近词大厅索引构建与道具协议扩展。
  3. 第三阶段：客户端 UI 道具图标、动效与对战试玩联调。
