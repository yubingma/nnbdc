🔥 核心机制亮点：精进勋章「多次获得与星级进阶（Stacking & Star Level）」
解决“一次性达成后失去挑战动力”的痛点，让每一次满分复习与早起都持续产生成就感
🎯

为什么精进勋章必须支持多次获得？

像「百发百中（100%全对）」、「极速心流（秒答连对）」、「破晓之翼（清晨学习）」属于用户日常高频发生的优秀自律行为。 若只能获得一次，用户在第 1 次拿过后，后续的满分测试将再无成就奖励。 因此我们设计了「实时计数角标（×N） + 阶段性星级突破（★1~★5）」双重机制！

×N

1. 实时计数叠层 (Stacking)

勋章左上角常驻显示获得次数（如 ×12）。每次再次达成，均弹出「百发百中 +1」并获得常规魔法泡泡奖励。

★

2. 里程碑星级进阶 (Star Tier)

累积达成 1次(★1)、10次(★2)、30次(★3)、60次(★4)、100次(★5满星宗师)。每升一星点亮下方金星并升级光效。

👑

3. 个人主页与排行榜炫耀

个人主页展示「百发百中 ×38 (★★★☆☆)」，学霸威慑力拉满，成为自习室与排行榜上的荣誉象征。

临近达成提醒 (Nudge)

当用户距离某勋章只差 10% 进度时（如差 5 个词解锁千词勋章），在学习完成页弹出轻量气泡，激励用户再学一组。

完成背词/打卡/测试瞬间，后端通过事件监听异步判定，符合条件即刻在响应中返回 new_badges 列表（支持返回多次累加与升星事件）。

3

高光全屏弹窗

App 端触发粒子光效 + 震动触感（Haptic）+ 矢量勋章 3D 翻转动效，带来强烈的仪式感与心理满足。

佩戴与海报分享

弹窗底部提供「立即佩戴挂件」和「发朋友圈炫耀」双按钮，顺畅承接后续社交传播路径。

🛠 技术方案：数据模型与规则引擎 (Spring Boot + Flutter)
符合奥卡姆剃刀原理，高扩展性与高性能，不增加冗余实体

1. 核心数据表设计 (MySQL / JPA)

表名 关键字段 说明
badge_definition id, code, name, category, tier, svg_code, is_stackable, condition_type, target_value, reward_bubbles 勋章元数据配置表（is_stackable=1 标识精进类可多次获得勋章，reward_bubbles 奖励魔法泡泡）
user_badge id, user_id, badge_id, obtain_count, star_level, unlocked_at, is_equipped, is_viewed 用户勋章拥有表（obtain_count 记录获得次数，star_level 记录 1~5 星级）
user_badge_progress id, user_id, badge_id, current_value, updated_at 多阶段累计型勋章的当前进度（可结合 Redis 缓存提速）

2. 规则引擎架构 (Event-Driven Badge Engine)

采用 Spring 的 ApplicationEventPublisher 事件驱动机制解耦：

  • 事件发布：用户打卡完成触发 CheckinSuccessEvent，测试满分触发 TestPerfectScoreEvent。
  • 异步监听：BadgeEventListener 接收事件，若为可叠层勋章，执行 obtain_count + 1 并计算是否触发升星门槛。
  • 幂等发放：更新进度并检查阈值，满足则写入 user_badge 并标记未读提示。
  • 前端消费：Flutter 端使用 flutter_svg 原生平滑渲染，弹出统一的 BadgeAwardDialog 仪式感弹窗。
