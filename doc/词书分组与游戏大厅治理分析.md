## 三、问题一：选书页面的分组关联是否合适

**结论：不合适，存在系统性错位。**

### 3.1 `大学` 分组是个垃圾桶（175 本 2024+ 新书）

| 实际类别 | 数量 | 本该去的分组 |
|---|---:|---|
| 考研类（红宝书/闪过/恋练有词/黄皮书/颉斌斌…） | **92** | `考研`（现有分组只有 11 本） |
| 四六级（四级/六级） | **23** | `四六级` / `大学英语四级` / `大学英语六级`（现有分组只有 15 本） |
| 专四/专八 | **16** | `英语专业` / `英语专业四级` / `英语专业八级`（现有只有 8 本） |
| 专升本 | **9** | 无此分组，需新建 |
| 高考 | 1 | `高考` |
| 新概念英语第四册(按单元) | 1 | `新概念` |
| 真·大学教材（新视野/新标准/新目标/全新版/高级英语…） | 31 | 保留 `大学` |
| 待定（成人本科学位、AB级等） | 2 | 待定 |

### 3.2 年级子分组被"架空"

- `初中` 分组里 2026 年导入的 **86 本**教材，全部堆在父分组；而 `初一`/`初二`/`初三` 三个子分组里**只有 2012 年的 2 本老鲁教版**。
- `高中` 分组同理：**75 本**新教材全在父分组，`高一`/`高二`/`高三` 只有 2012 年的牛津/人教版老书。
- `小学` 分组：2026 年 29 本，其中 24 本已经正确分到三~六年级子分组，但 **5 本漏了**（新概念第一册、鲁教版五四制六年级上册/下册等）。
- `大学` 下的 `大一`/`大二`/`大四` 2026 年新书为 0，`大二`/`大三` 里那 3 本新书是**错放**的（下面 3.4）。

### 3.3 `其他` 分组实际已被隐藏

客户端 `select_book.dart` 硬编码排除了 `其他`：

```dart
var topGroups = dictGroupsData.where((g) =>
  (rootId != null ? (g.parentId == rootId) : ...)
  && g.name != 'root' && g.name != '其他').toList();
```

也就是说 `其他` 组里那 76 本 2012 年老书**用户早就在选书页面看不到了**，但它们在游戏大厅"所有单词"里还活着。

### 3.4 明确的错放（跨大类的三重归属）

| 词书 | 当前分组 | 问题 |
|---|---|---|
| 2027考研英语红宝书乱序 | 大三 + 大二 + 大学 + 考研 | 考研书不该进大学年级 |
| 专升本3500乱序 | 大三 + 大二 + 大学 | 同上 |
| 高考3500乱序 | 大三 + 大二 + 大学 + 高考 | 高中书不该进大学 |
| 《鲁教版初中英语》6上/6下 | 初一 + 初中 + **小学六年级** | 五四制六年级 = 初一，不该同时在小学六年级 |

### 3.5 其他小问题

- 分组名 **`CERF` 拼写错误**，应为 `CEFR`（组内 22 本书名都是 `CERF*`/`CEFR词汇表`，命名本身也不统一）。
- `CERF` 组里混进了 `多邻国核心词汇 初级/中级/专业` 3 本，与 CEFR 等级体系无关。

## 四、问题二：下架「2024 年之前」词书的真实影响

### 4.1 需求本身是可行的

- 客户端**只有选书页面**读 `visible`（`select_book.dart` 第 126/173/382/585 行）。
- **书桌/词表页（`word_lists.dart`、`desk_section.dart`）不读 `visible`**，走的是 `learning_dict` + 本地 `dict` 表 → 已选老词书的用户不受影响，学习、下载都不受影响（服务端下载接口也不校验 `visible`）。
- 存量规模：**34935 条 `learning_dict` 记录、16634 名用户**已经选了 2024 年前的词书 —— 所以"不打扰存量用户"这条必须守住，`visible` 方案是对的。

### 4.2 但一刀切会让选书页面塌掉一半

按 `create_time < 2024-01-01` 下架后：

**整个一级分类消失（12 个）**：
`GRE`、`托福`、`新概念`、`PETS`、`商务英语`、`少儿`、`职称`、`自考`、`蒲公英`、`行业`、`许国璋`、`走遍美国`

> 这 12 个基本都是"年代久远"的类别，消失符合预期。

**一级分类存活但子分组消失（刚需受损）**：

| 一级分类 | 下架后剩余 | 消失的子分组 |
|---|---:|---|
| 初中 | 86 | **初一、初二、初三** |
| 高中 | 75 | **高一、高二、高三** |
| 小学 | 53 | **小学一年级、小学二年级** |
| 大学 | 181 | **大一、大四** |
| 四六级 | 4 | **大学英语四级、大学英语六级** |
| PETS | 0 | 5 个级别 |

**根因不是"老书该不该下架"，而是"新书没被放进对应的年级子分组"。** 只要先做第三章的分组修正，初一/初二/初三 各有 30 本左右新教材，下架就完全安全。

## 五、问题三：游戏大厅

### 5.1 机制层面：大厅和选书页面共用分组，且大厅不认 `visible`

`GameHallBo.getGameHallWords()` → `DictGroupBo.loadDictGroupsAndDicts()` → `DictGroup.getAllDicts()`，
整条链路**没有任何 `visible` / `is_ready` 过滤**，SQL 就是：

```sql
SELECT d.* FROM dict d
INNER JOIN group_and_dict_link gdl ON gdl.dict_id = d.id
WHERE gdl.group_id = :groupId
```

推论：

1. 光把词书 `visible=false`，**游戏大厅照样抽得到它**（现有 25 本已下架词书就是证据）。
2. 想让游戏大厅不抽老书，**当前只能物理删掉 `group_and_dict_link`**。
3. 而 `group_and_dict_link` 就是选书页面的数据源 —— **删了，选书页面也一起没了**。
4. `Hall` 的词表在**首次有人进入大厅时构建，然后常驻进程内存**（`Russia.gameHalls` 无淘汰逻辑），改库后必须**重启 `nnbdc-service`** 才生效。
5. 大厅词表为空时，`Hall.getWordRandomly()` 会在 `wordList.get(0)` 抛 `IndexOutOfBoundsException` —— **空大厅不是"没题"，是服务端报错**。

### 5.3 游戏大厅里"不合适"的词书

**缺失（该有却没有）**：
- `考研` 大厅只有 11 本，而 **92 本考研书躺在 `大学` 分组**里 → 大厅少收了一大半。
- `大学英语四级/六级` 大厅各只有 1 本（其中四级那本还是已下架状态），而全库 2024+ 的四六级类词书有 **27 本**（其中 23 本躺在 `大学` 分组里）。
- `英语专业四/八级` 大厅各 3 本，而全库 2024+ 的专四专八类词书有 **18 本**（其中 16 本躺在 `大学` 分组里）。
- `初一~高三` 大厅全部指向"只有老书"的年级子分组，2026 新教材一本都没进来。
- 没有 `专升本`、`CEFR`、`雅思(仅2本)` 等对应大厅（是否要补，见决策项）。

**错误（不该有却有）**：
- `大二`/`大三` 大厅里混进 `高考3500乱序`、`专升本3500乱序`、`2027考研英语红宝书乱序`。
- `所有单词` 大厅 = `root` 分组，池子里包含 `其他` 分组那 76 本**用户在选书页面根本看不到**的老书，以及全部 25 本已下架书。语义上"所有单词"应当是"所有**可选**词书"。
- `大学英语四级` 大厅池里唯一一本是 `visible=false` 的 2020 年老书 —— 这个大厅现在就已经名不副实。

### 5.4 遗留的机制性 Bug（会直接阻碍你的整改）

| # | 位置 | 问题 |
|---|---|---|
| B1 | `app/lib/util/sys_db_sync.dart:133` | 解析 `group_and_dict_link` 的 DELETE 用 `recordId.split('-')`，而增量日志写入端 `DictBo.java:595`、`DictImportBo.java:1158` 用的是 `group_id + "_" + dict_id`（下划线）。全量快照 `SysDbSyncBo.java:372` 用的是 `-`。→ **增量删除永远不生效，词书"移出分组"后客户端仍显示在旧分组里** |
| B2 | `DictBo.updateSystemDict()`（`DictBo.java:591-624`） | 先 `DELETE FROM group_and_dict_link WHERE dict_id = :dictId` 清空**全部**分组，再只插入 `targetDictGroupId` + 大厅对应分组。→ 用它给一本挂在 `{高中, 高二}` 的书做下架，会**顺手删掉 `高二` 归属**。管理端 UI 只传一个分组（`dictionary_management.dart:920`） |
| B3 | `AdminController.saveDictGroup` → `DictGroupBo` | 新建/改名分组**不写 `sys_db_log`**（只有 DELETE 写了，`DictGroupBo.java:181`）。→ 改 `CERF`→`CEFR` 客户端看不到 |
| B4 | `Russia.gameHalls` | 大厅词表进程内永久缓存，改库必须重启服务 |
| B5 | 管理端下拉框 | `dictionary_management.dart:478` 和 `dict_import_management.dart:79` 只列 `root` 的直接子分组，**根本选不到 `初一`/`小学三年级` 这类二级子分组** —— 这正是 2026 新教材被塞进 `初中`/`高中` 父分组的结构性根因。（批量导入页 `batch_import_management.dart:55` 用的是 `getAllDictGroups()`，可以选到全部分组，是唯一可用的正路） |
| B6 | `SystemBo.getSystemData()` | 全量快照 BO 没有任何 Controller 暴露，客户端也没有调用方（死代码）。若要走"全量重刷"来消除 B1 的脏数据，需要先确认这条链是否真的断了 |

## 六、建议方案

> 核心判断：**你的两个诉求（选书页面下架 / 游戏大厅移除老书）在当前模型下可以合成一件事做，但必须先补数据、先修机制，否则会打穿 19 个大厅和 6 个年级分组。**

### 阶段 0：修机制（代码，不改数据）

| 步骤 | 内容 | 验证 |
|---|---|---|
| 0.1 | 给 `loadDictGroupsAndDicts` / `getGameHallWords` 加 `AND d.visible = true AND d.is_ready = true` 过滤 | 让 25 本已下架书从大厅消失，且不必删关联 |
| 0.2 | 统一 `group_and_dict_link` 的 `recordId` 分隔符为 `-`（改 `DictBo:595`、`DictImportBo:1158`） | 客户端能收到删除 |
| 0.3 | 新增 `batchUpdateDictVisibility` 接口：**只改 `visible` + 写 `dict` UPDATE 日志**，绝不动 `group_and_dict_link` | 批量下架 332 本时不会破坏多分组归属 |
| 0.4 | `saveDictGroup` 补写 `dict_group` 同步日志 | 分组改名能同步 |
| 0.5 | 管理端两个下拉框改为**完整分组树多选** | 以后导入不再被迫塞父分组 |

### 阶段 1：修正分组归属（数据，可逆）

把 2024+ 的新书放进正确的分组。规则如下（数量为生产库实测）：

1. `大学` → `考研`：**92 本**（书名含 考研/硕士/红宝书/闪过/恋练有词/黄皮书/颉斌斌/锐记/背考通/你还在背/十天搞定考研/研词有理/考博/单词之间/何凯文/马天艺/王晶婷/达叔/陈正康/果然如词…）
2. `大学` → `四六级`：**23 本**（四级 4 / 六级 19）
3. `大学` → `英语专业四级` / `英语专业八级`：**16 本**（专四 9 / 专八 7）
4. `大学` → 新建 `专升本`：**9 本**
5. `大学` → `高考`：`高考3500乱序` 1 本
6. `大学` → `新概念`：`新概念英语第四册(按单元)` 1 本
7. `初中` → 年级：**79 本**（七年级→初一 34 / 八年级→初二 31 / 九年级→初三 14）；教辅类（中考词汇闪过、20天背完中考、初中英语大纲词汇、初中英语常考短语、维克多、蝶变、新概念第二册）7 本留在 `初中`
