01为什么需要

词表是「全量视图」：一本词书有多少词，列表就有多少条。但用户在这本书里的真实处境是三种状态混合的，而现在界面只给了一个总数。

  • 已掌握的词不会离开列表。词书词表明确保持"掌握后不移除"（dict_words.dart:92），用户点完"掌握"，那条词还留在原地。
  • 列表只回答"有多少"，不回答"是什么"。标题右侧只有一个总词数（word_list.dart:3171-3182）；书桌卡片也只给到"已掌握 N · 已取词 M / 总 T"（desk_section.dart:595），那 N 个具体是哪些，用户翻不出来。
  • 学习取词早就跳过已掌握的词（learning_service.dart:805-808），于是用户"肉眼扫一遍还剩多少"的直觉和系统"实际还会取多少"的行为是脱节的。
  • 三态信息其实已经在词表里可视（左侧环形徽章，见第六节），只是从来没被当作可筛选的维度。

因此这个功能是视图层的裁剪，不是学习策略的变更。它服务三类动作：刷书（只看未学习，看还剩多少生词）、复盘（只看学习中，盯正在消化的那批）、清点（只看已掌握，看我拿下了什么）。

02三态定义

三态沿用现有的批量学习状态判定（word_bo.dart:633-660），本次不改判定口径：

状态判定用户视角环典型动作
未学习词书收录，但用户无学习记录还没排进学习计划的储备词空环刷书看剩余量
学习中有学习记录，且不在「已掌握」词书已取词、正在按 FSRS 推进半环复盘当前那批
已掌握在用户的「已掌握」词书里已经拿下的词满环清点、导出

判定只有这一个事实源。筛选层不另写判定，保证"筛选结果的条数"与书桌卡片上的"已掌握 N"永远对得上。

03交互形态：三勾选 + 每行带数量

入口

与「排序」同级，放在「更多」菜单里（该菜单已按语义分组，排序行位于"设置与输出"组，word_list.dart:2857-2858）。行内直接显示当前态，与排序行完全对称（排序行现状为 word_list.dart:3047-3048）：

  • 排序: 字母序
  • 筛选: 未学习+学习中（三项全勾时显示 筛选: 全部）

不做顶栏常驻筛选胶囊：切换筛选是低频意图，顶栏已有「S | 位置 | E」定位胶囊，再插一个会挤掉极简感。

规则

  • 默认全勾，与现状完全一致，不惊吓已有用户。
  • 每行带数量（未学习 1200 / 学习中 320 / 已掌握 980）。这是本方案最大的附加价值：即使一个字都不勾，用户一眼就读到了这本书的结构；三数之和恒等于全书词数。
  • 至少保留一项：取消最后一项勾选时自动回落到"全部"，不弹报错。
  • 菜单摘要：一项显示该项名，两项显示 A+B，三项显示全部（避免行内文字过长）。

为什么是多选，而不是"全部 / 某一态"四选一

三态是三个互斥集合，而用户最常用的意图之一是"未学习 + 学习中"（= 我还没掌握的）。单选要枚举 7 种非空组合，既不自然也放不下；多选天然覆盖，且与环的三态语义一一对应。

04与既有机制的关系

维度规则理由
学习取词完全不受影响筛选只作用于"看"，不改"学"；已掌握的词本来就取不到
各浏览模式浏览 / 遮挡中文 / 遮挡英文 / 说中文 / 说英文 / 翻译例句 / 拼写（打字、手写）/ 随身听 全部生效否则一页藏了、另一页还在念，状态自相矛盾
导出 PDF、AI 短文按当前筛选结果所见即所得，否则导完还要手动删

状态变化词被掌握 / 取消掌握后，若不再属于勾选集合，条目立即移出条目消失即是操作生效的反馈；「1.5s 撤销」本次未做（见第十节遗留项）
记忆按「用户 + 词书」分别记住勾选组合，落在设备本地（与主题 / 字号 / 引导标记同源的 localParams）"这本书只看未学习"的意图应当被记住，换书不串味；跨设备不同步的原因见第十节
适用范围仅"可能含多种状态"的词表显示：词书词表显示；「已掌握」「生词本」「学习中」「今日词」「错词」等虚拟/单一态词表不显示在这些表里筛选是恒等或恒空，只会制造困惑
访客 / 未登录不显示筛选没有学习状态可言

05空态

  • 只看未学习 → 空：这本词书的生词都已排进学习计划 ＋「显示全部」
  • 只看学习中 → 空：暂时没有正在学习的词 ＋「显示全部」
  • 只看已掌握 → 空：还没有已掌握的词 ＋「显示全部」
  • 多选组合 → 空：当前筛选下没有单词 ＋「显示全部」

空态一律提供一步出口（一键回到全部），不留死胡同；不在空态里再挂学习入口，避免多出一个跳转面。

06视觉锚点：环即状态

词书词表传的是"不显示词内进度、只显示学习状态"的配置（dict_words.dart:483），因此左侧环形徽章正好按三态渲染（word_list_item_layout.dart:263-269）：

12
未学习
13
学习中
14
已掌握

这意味着筛选不需要新建任何视觉语言：勾什么状态，列表里就是哪些颜色的环。它同时给出一条可直接机测的验收口径——可见词的环颜色集合必须严格等于勾选集合。

顺带记录一个一致的产品逻辑：词书词表的环表达"学没学过"（状态），学习类词表（学习中 / 今日词 / 已掌握）的环表达"熟练到哪了"（掌握度）。同一元件在两类页面承担两种语义，各自都成立，本次不动。

已知例外：被书签的单词渲染为实心主题色圆盘，会盖掉状态环（word_list_item_layout.dart:229-257）。即"既被书签、又是未学习"的词，看不到它的空心环。这不是筛选缺陷，验收时需按"书签词以盘代环、不计入环颜色比对"处理。

07验收口径

  • 三态数量之和严格恒等于全书词数，任何时刻（含刚掌握 / 刚取消掌握的瞬间）都成立。
  • 可见词的状态集合严格等于勾选集合（书签词以盘代环，按例外处理）。
  • 切换浏览模式（说 / 拼写 / 随身听等）后，可见词集合与浏览模式完全一致。
  • 在"未学习"视图下标记掌握，该词立即移出列表（在"已掌握"视图下取消掌握同理）；已由 test/word_list_status_filter_test.dart 覆盖。
  • 重进页面后，筛选态与可见集合保持一致；书签位置不发生漂移（书签单词被筛掉时中段显示「—」，取消筛选即回原位）。
  • 导出 PDF / AI 短文的结果与当前可见集合一致。

08不改动的既有边界（记录在案）

  • 取消掌握当天的状态错位：取消掌握只把词移出「已掌握」词书并丢进生词本，不重置该词学习记录里的稳定性（dao.dart:1998-2030）。于是当天它的稳定性仍 ≥ 毕业阈值，被判定为"未学习"；但它同时因"已有学习记录"而不会被取词。跨天清理会删除这类记录（dao.dart:1429-1437，调用点 learning_service.dart:107），次日它真正回到"未学习"并重新可被取词。
    本次决策：不改判定口径，该错位最多持续当天，且能自愈；此条作为已知现象长期记录，不做前端托底掩盖。
  • 书签盘覆盖状态环：既有设计，本次不动。
  • 词书词表传入的进度提供者与"掌握度"标签是走不到的死参数（dict_words.dart:255-265、dict_words.dart:483）：仅记录，不在本次清理。

09不在本次范围

  • 批量"把筛选结果标记为已掌握"（扫一眼全认识，一键清空）—— 价值明确，但属于独立动作，留待下一版。
  • 按熟练度分档筛选（生 / 熟 / 忘）。
  • 其他筛选维度（错词、收藏、单元、词频）。本次只把"学习状态"这一个维度做透。
  • 学习取词策略的任何变更（现已自动跳过已掌握的词，足够）。

10决策记录

议题结论说明
筛选维度三态（未学习 / 学习中 / 已掌握）不止"已掌握 / 未掌握"二分，未学习必须独立可筛
三态判定口径不动，沿用现有实现含稳定性阈值，已知的当天错位接受并记录（见第八节）
交互形态三勾选 + 每行带数量多选覆盖"未学习+学习中"等组合意图
默认态三项全勾（= 全部）与现状一致
入口位置「更多」菜单内，与"排序"同级对称不做顶栏常驻胶囊
适用范围仅词书词表单一态/虚拟词表不显示

补充决策（落地阶段）

议题结论说明
筛选偏好存放设备本地的 localParams，键含 userId 与 dictId视图偏好与主题 / 字号 / 引导标记同源，且天然按用户隔离。跨设备同步本次不做：词书卡片的 book_mark 增量同步只携带 position / spell（连 sort_alg 都不同步），要让筛选跨设备需要动服务端与生产库 DDL，须单独授权
书签坐标口径position 记为"当前视图内序号"；被筛掉时记 -1（书签单词保留）取消筛选时按单词重新定位，位置不漂移；切排序时同样不把被筛掉的书签改写成列表首词
空态出口统一为「显示全部」一步不在空态里再挂学习入口

落地记录（已实现）

  • 新增 api/word_status_filter.dart：三态枚举 + 多选筛选值类型（编码 / 标签 / 切换 / 回落）+ 三态数量。
  • WordBo：分页、定位、三态数量三条查询都支持状态筛选，三态判定以 LEFT JOIN 下推到 SQL（不把上万 wordId 塞进 IN 列表）；未启用筛选时走原路径，历史行为不变。
  • DictWordsProvider：筛选取值 / 保存 / 计数，以及"该状态在当前筛选下是否可见"。
  • WordListController：切筛选重定位、书签隐藏语义、掌握 / 取消掌握后即时移出、标题"可见 / 总数"。
  • 词表页：更多菜单新增「筛选: …」行、三态多选弹窗（带数量）、空态、S|n|E 中段「—」。
  • 单测：test/word_status_filter_test.dart（值类型 + SQL 三态筛选 + 偏好持久化）、test/word_list_status_filter_test.dart（控制器：书签隐藏与恢复、标题计数、掌握即时移出）。
