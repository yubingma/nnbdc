# 方案设计：批次调度中练习题优先与 List 环节唯一次收敛

## 1. 背景与问题分析

### 1.1 问题描述
在当前批次学习流转中，当批次内单词由于规则或答题情况不同而具有不同轨道长度时（例如旧词答对为 `[测评, List]` 长度 2，答错为 `[测评, 反向互补, List]` 长度 3）：
1. 10 个词轮流完成测评后：
   - 答对的单词已推进至末位 `List` 环节；
   - 答错的单词推进至中间的 `反向互补` 错题环节。
2. 此时所有单词的 `todayLearnedTimes` 均为 1，原有排序仅依据 `eff`（min(times, length)）和 `learningOrder`，导致排在前面的答对词被优先调度；
3. 答对词的当前环节为 `List`，系统提前触发了进入「本组单词」列表页；
4. 列表结算后，系统回到做题页继续调度答错词做 `反向互补`；
5. 答错词做完后又推进至 `List` 环节，导致**同一批次重复进入两次 List 页面**。

### 1.2 目标
- **练习题优先原则**：批次调度中，只要批次内存在尚未完成所有普通练习题的单词（`currentStep != 'List'`），必须优先调度其完成练习题；
- **全批次 List 唯一次收敛**：只有当批次内**所有未掌握单词均已完成普通题目到达 `List` 环节**时，全批次才统一切入进入「本组单词」List 页面，避免提前和重复进入。

## 2. 核心改动点

### 2.1 封装批次内单词调度排序比较器
- **文件**：`app/lib/api/bo/study_bo.dart`
- **设计**：
  提取统一的批次单词排序比较函数 `_compareBatchWords`：
  1. **完成状态**：已掌握（`isEffectivelyMastered`）或已走完全部轨道（`isTodayFinished`）的单词排在最后；
  2. **环节类型优先级**：仍处于普通练习题（`currentStep != 'List'`）的单词，**严格优先于**已到达 List 等待状态（`currentStep == 'List'`）的单词；
  3. **练习步数推进**：对于同处于普通练习题（或均处于 List）的单词，按 `todayLearnedTimes` 升序排列（实现横向平稳轮流做题）；
  4. **批次内序号**：步数相同时，按 `learningOrder` 升序排列（从左到右）。

### 2.2 统一 `getWord` 中的两处批次排序
- 将 `getWord` 中确定当前词（L631-648）与确定下一个词（L774-788）的两处排序替换为统一的 `_compareBatchWords`。
