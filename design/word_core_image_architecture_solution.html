一词多义·核心意象（Cognitive Image Schema）落地方案

📅 制定时间：2026-09
🛠 涉及模块：大模型 API / 服务端批处理 / Flutter 动态拓扑渲染
🎯 核心目标：彻底根治多义词死记硬背痛点，构建辐射认知网络

1. 背景与认知语言学理论底座

在传统背单词应用中，“一词多义”是用户公认最痛苦的记忆深水区。传统词典往往将一个单词的七八个释义并列、孤立地死板罗列（例如 spring：春天、泉水、弹簧、跳跃、引爆）。用户无法在脑海中建立联系，只能死记硬背，极易产生混淆与遗忘。

认知语言学（Cognitive Linguistics）表明：自然语言中的绝大多数多义词并非偶然同形，而是由一个原始的核心图式（Image Schema）或物理动势，在人类漫长演进中通过隐喻（Metaphor）与转喻（Metonymy）向不同生活领域辐射延展出的概念网络（Radial Categories）。

💡 案例剖析：spring 的认知统一性

spring 的核心意象是“力量蓄积后的突然向上弹涌”：
• 跳跃（v.）：身体蓄力后向上一跃的动作本身；
• 弹簧（n.）：被压缩后瞬间反弹的机械构件；
• 泉水（n.）：地下水受压后咕咚咕咚向上喷涌的水体；
• 春天（n.）：严冬过后大地复苏、生命破土迸发的爆发性季节。
点破这一原点动势，即可帮助用户“一通百通”。

2. 大模型能力边界与选型评测

2.1 DeepSeek 可以生图吗？

结论：DeepSeek 自身不提供文生图（Text-to-Image）功能。
DeepSeek（包括 DeepSeek-V3 与 DeepSeek-R1）是纯文本与强逻辑推理的大语言模型，其 API 输出的是字符/结构化 JSON，无法直接生成图像像素点阵。

但在本项目中，大模型真正不可替代的价值是“语言认知分析大脑”，负责： 1. 深入印欧/日耳曼/拉丁词源，提炼物理意象原点； 2. 解析各释义跨越不同生活领域的隐喻演变脉络； 3. 输出干净轻量的结构化 JSON 供客户端驱动。

2.2 DeepSeek vs 阿里通义千问（实测 20 词对比）

我们连接本地数据库，提取了 20 个极具代表性的一词多义单词（charge, bank, fine, scale, court, sound 等），对两家旗舰模型进行了实机横向对比：

评测维度 DeepSeek (deepseek-chat) 阿里通义千问 (qwen-max)
意象提炼高度 ★★★★★（深刻触及原始词根与空间几何图式，抽象层级高） ★★★☆☆（容易以偏概全，常把某个具体子释义误当成核心意象）
引申解释自洽性 ★★★★★（闭环逻辑：【动势】+【场景投影】=【释义】，透彻严密） ★★★☆☆（偏好打比方“如同……”，偶有牵强硬凑）
同形异义鉴别 ★★★★★（对 scale-鱼鳞、fine-罚款 等独立词源客观指出，不瞎编） ★★★★☆（能够鉴别明显无关词源，但底层认知感知偏弱）
API 成本与响应 极低（输入 ¥1/M，输出 ¥2/M，吞吐极高） 中等（qwen-max 单价相对偏高）
⚠️ 评测实录印证（以 charge 为例）

• DeepSeek 提炼意象为“往容器里装填、压入并承载负荷”（源自古法语 chargier 装载车马），完美穿透：充电（装电）、收费（向账单压入债务）、指控（向被告压入罪责）、负责（把职责装在自己身上承载）。
• Qwen-Max 提炼为“向前冲、注入力量”，在解释收费时变成“注入资金”，解释负责时变成“注入责任”，比喻生硬，未能找到原点图式。

3. 图像呈现路线演进与技术决断

为核心意象配图，存在两条不同路径：

形态 A：纯概念隐喻位图
（由 AI 渲染无文字的高级 3D 概念插画，熔铸弹簧、泉水、破土繁花于一炉）
形态 B：自适应辐射引申拓扑图
（中心枢纽 + 外围释义胶囊 + 贝塞尔连线 + 连线引申标签，支持点击联动）

为什么必须选择“结构化数据驱动 + App 原生矢量渲染”？

  • 拒绝生图模型的乱码灾难：文生图大模型在排布中文小字时极易糊字、乱码、折行错位；而代码原生绘制矢量文字，在任何屏幕倍率下都保持 100% 绝对清晰。
  • 原生交互与联动：用户点击任一释义节点，连线高亮激活，下方自动联动例句与考点；支持暗黑模式自适应。
  • 带宽与性能极佳：一张位图需 500KB~1MB，而结构化 JSON 仅需 300~500 字节，请求耗时极短，加载丝滑无感。
  • 终极黄金形态（图文合璧）：中心枢纽背景内嵌无文字的 AI 概念微缩图，外围由 Flutter 原生 Canvas/CustomPainter 绘制贝塞尔引申星轨。

4. 数据结构与接口契约设计

4.1 服务端数据表规范（遵循项目统一规范：32位UUID主键、单数下划线命名）

CREATE TABLE `word_core_image` (
  `id` VARCHAR(32) NOT NULL PRIMARY KEY COMMENT '主键UUID',
  `word_id` VARCHAR(32) NOT NULL COMMENT '关联系统已有word.id',
  `spell` VARCHAR(100) NOT NULL COMMENT '单词原形(冗余存储，加速检索与排查)',
  `core_image` VARCHAR(128) NOT NULL COMMENT '核心动态意象短句',
  `image_schema_desc` VARCHAR(255) NOT NULL COMMENT '核心原点图式与动势阐释',
  `branches_json` TEXT NOT NULL COMMENT '引申网络结构化JSON数据',
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 0-待审核 1-已发布',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY `uk_word_id` (`word_id`),
  KEY `idx_spell` (`spell`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

5. 落地推进实施路线（Roadmap）

第一阶段：离线批量处理与高质量建库（1~2天）

  • 编写 Python/Node 服务端批处理脚本，筛选词库中考研、四六级、托福、雅思等高频核心多义词（约 2000~3000 个）；
  • 调用 DeepSeek-V3 API 批量生成结构化 JSON，通过格式校验器直接清洗入库，关键重点词人工抽验；

第二阶段：Flutter 原生拓扑组件封装（2~3天）

  • 基于现有 HTML 验证成功的贝塞尔算法，封装 Flutter 原生 CoreImageRadialWidget 组件；
  • 完美接入 App 单词详情页（WordDetailPage），与已有的 meaning_item 和例句体系无缝联动；

第三阶段：记忆测试场景渗透（后续演进）

  • 在做一词多义辨析题或复习卡片时，提供“意象纽带提示”，引导用户通过原点动势推导词义，达到深度神经突触连接。
