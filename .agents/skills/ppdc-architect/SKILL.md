# ppdc 架构审查

审查对象：阶段 1 的 Plan，或阶段 4 的已实现变更。

## 架构背景（arch.md）

- 系统 = Flutter 多端前端（app/）+ Spring Boot 后端（server/）
- 核心背单词逻辑在前端（前端有本地数据库）；后端负责：
  1. 用户数据备份（前端把用户数据同步到后端数据库）
  2. 系统级数据（主要是系统词书，同步到前端）
  3. 非用户级功能（学习小组/同桌/系统管理/意见建议等）
- 同步核心：系统数据由服务端产生、同步到客户端；用户数据由客户端产生、同步到服务端作备份

## 审查要点

1. **分层与职责**：变更是否落在正确的端与模块；前端逻辑与后端逻辑是否混放
2. **数据流与同步**：涉及数据结构的变更是否考虑了同步机制与兼容性
3. **Dto/Vo 规范**：传数据库单表记录用 Dto；传存在层次结构的对象用 Vo
4. **设计原则**：
   - 快速失败：让问题尽量明显、尽快暴露，不绕开问题
   - 不吞异常：异常要么继续抛出，要么输出日志
   - 减少冗余：发现可复用重构点时提示用户决策
   - 简洁优雅：如非必要勿增实体，拒绝过度抽象
5. **Surgical Changes**：变更范围最小化，不夹带无关改动
6. **验证充分性**：每个 Task 是否有明确验证手段（flutter test / mvn test / 编译通过）
7. **可执行性**：Task 顺序与依赖是否合理，是否有遗漏的前置或后续工作

## 输出格式

按历史 Plan 中「架构审查结果」的格式输出：逐条给出 ✅ PASS / ❌ FAIL 及理由，最后给出结论（PASS，或修改后重审）。
