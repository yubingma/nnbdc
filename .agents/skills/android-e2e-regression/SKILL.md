# Android 真机端到端回归测试

用 ADB 驱动一台真实 Android 手机，走完「注册 → 选词书 → 定计划 → 学完当日计划 → 打卡 → 断网恢复 → 跨天连续打卡 → 注销」的完整业务，并把每一步的结论写进一份报告。全程只有两处碰后端：读登录验证码、核对云端落库结果。

## 三条硬规矩

### 1. 分母固定，跑不到的记「未执行」

`run_regression.py` 顶部 `CASES` 是全部用例清单，报告分母永远是它的长度。执行到一半挂掉时，没跑到的用例不会消失，而是记成 **未执行** —— 报告里一眼能看出「这次根本没跑到」，不会被误读成「只坏了一步」。

### 2. 只有通过和失败，没有「警告」

断言不成立就是 **失败**。历史版本把「30 词没学完」「打卡没落库」「跨天没连上」都降级成「警告」，整轮仍然返回成功 —— 这种「假绿」比测试覆盖不足更危险，已经全部删除。

### 3. 控件按稳定标识点，不按文案、不按坐标

App 用 `Semantics(identifier: 'e2e_xxx')` 把标识写进无障碍树的 `resource-id`，测试按它定位。文案改字、换分辨率都不影响；标识找不到就是失败，绝不退回按文案猜。

只有三类东西允许按文案找：
- **断言要读的展示内容**（如「第 1 组 · 新词测评 3/10」「2,984 词」「同步失败」）；
- **App 内置的系统输入控件**（`android.widget.EditText`，邮箱与验证码框）；
- **瞬态系统弹窗**（「导入词书」的「完成」按钮）。

### 答题正确性怎么判

- 先停进程拉一份本地 SQLite 快照（`db.sqlite` + WAL 一起取，避免撕裂），从 `meaning_items` 读出每个单词的真实释义；
- 选择题的每个选项有稳定标识，选项文案从节点里读出来；
- 选项文案里能命中该词释义最多的那一个才算「正确选项」；判不出唯一答案就不判，不会瞎点。

### 端云一致性到底比对了什么

按当前账号，把本地 SQLite 与生产库逐条、逐字段对齐（`local_db_auditor.py:216` 起）：

| 表 | 比对内容 |
|---|---|
| 评分流水 | 先比「有哪些条」（本地有云端没有的、云端有本地没有的都列 id），再按 id 比 `rating`、`stability`、`difficulty`、`scheduled_days`、`elapsed_days`；浮点按相对误差 1e-6 容差 |
| 打卡 | 按日期比「哪几天有」，再比每天的打卡文案 |
| 每日学习统计 | 按日期比复习条数（`review_count`）；专注时长是本地一直在跑的计数器，同步时点不同必然有差，故意不比 |

比对本地的日期时会先把本地存的 epoch 秒换算成 `YYYY-MM-DD`，再和云端按日期对齐。

### 反向用例

- **断网**：关 Wi-Fi 与移动数据 → 进同步页点「立即同步」→ 必须明确报失败，不能假报成功；恢复网络后必须补上。
- **拒绝录音权限**：`pm revoke` 会直接杀掉进程，所以先撤权再启动，然后切「说释义」，验证进程不重启且有权限说明。
- **杀进程**：答题中途 `force-stop` 再启动，验证进度还在原位。

## 执行

```bash
python3 -u .agents/skills/android-e2e-regression/scripts/run_regression.py --no-email
```

- `--plan N`：今天学多少词，默认 5。词数直接决定学习、跨天两段循环的长度，是控制总耗时最有效的旋钮（10 词约 17 分钟，5 词约 11 分半）。
- `--no-email`：跳过邮件推送（不影响结论）。
- `--serial <设备号>`：多台设备时指定。
- `E2E_DEBUG=1`：打印学习循环每一轮抓到的状态，用来定位「卡在哪张卡上」。

产物：
- 报告 `tmp/e2e_report/report.html`
- 截图 `tmp/e2e_report/screenshots/`

## 耗时与快慢

`uiautomator dump` 单次约 1.5 秒，是整条测试的成本底座；界面在动画中间时它会返回空树，所以要等界面落定再抓。已知的耗时大头：

实测一次完整 28 条用例：**699 秒（11 分半）**，`--plan 5`。分布大致是：

| 环节 | 大致耗时 | 说明 |
|---|---|---|
| 注销 + 注册登录 | 40s | 真机注销会清本地库，无法跳过 |
| 词书导入 | 24s | 挑「够用且词数最少」的词书，导入最快 |
| 学完当日 5 词 | 190s | App 每个词要走多个环节，偶尔还会「本环节重练」 |
| 跨天第二天 | 155s | 昨天的词今天到期复习，卡片量由昨天的作答量决定 |
| 杀进程 / 拒绝录音权限 | 80s | 各含一次冷启动 |
| 断网 + 恢复 | 50s | 两次手动同步 + 云端核对 |
| 本地库快照与推送 | 35s | 库约 194MB，一次拉取 10 秒以上 |
| 其余（连接、启动、导航、计划、审计、注销等） | 125s | |

优化方向只有两个：减少抓界面的次数、减少拉整库的次数。不要再加 `sleep` 硬等。

已知还能再省的地方（尚未做）：学习前的释义已经从生产库直接查（0.5 秒），不再为此拉整库；
但审计与跨天仍需各拉/推一次 194MB 的库，这是目前最大的一块固定成本。

## 老版本覆盖升级检查（单独一条）

装包升级与本地库迁移不在上面 28 条里，单跑：

```bash
python3 -u .agents/skills/android-e2e-regression/scripts/run_upgrade_check.py
```

它做的是真事：卸干净 → 装线上正式包（`https://www.nnbdc.com/app/nnbdc-android.apk`，缓存到 `tmp/e2e_artifacts/`）→ 用邮箱验证码登录并让它导入词书 → 覆盖安装新手包 → 核验。核验项：

| 用例 | 断言 |
|---|---|
| 老版本安装包就位 | 安装包存在且大小正常 |
| 老版本可启动 | 老版本启动后在前台 |
| 老版本登录成功并产生本地数据 | 真机输入邮箱验证码进主界面 |
| 覆盖安装新手包 | 新 versionCode > 老 versionCode，数据未被清空 |
| 升级后 App 正常启动且仍是登录态 | 不崩、直接进主界面、没被踢回登录页 |
| 升级后本地库结构升到当前版本 | `PRAGMA user_version` 已升到 63 |
| 升级后旧数据仍在 | `users`、`dict_words` 行数不为零 |
| 升级后端云同步正常 | 「云同步状态」卡片还在，同步可用 |

报告：`tmp/e2e_report/upgrade_report.html`。全程约 4 分钟，大头是两次 421MB 装包。

注意：老版本安装包里没有测试标识，驱动它必须按中文文案找按钮（只在这条检查里出现，不影响主回归）。协议行整行可点，点中心会打开《用户协议》，只有点最左边的圆圈才是勾选。

## 常见问题

1. **`adb devices` 为空**：检查 USB 调试授权；`adb kill-server && adb start-server`。
2. **用例大面积失败且报「找不到标识」**：装的是旧包，重新 `flutter build apk --debug` 并 `adb install -r`。
3. **验证码取不到**：确认手机网络能访问 `back.nnbdc.com`，且 `~/.zprofile` 里有数据库口令。
4. **断网用例失败**：先看是「没切到断网」还是「切了但 App 不报失败」。前者是 `svc wifi/data` 没生效，后者是 App 的问题，不要改测试去迁就。
5. **设备中途掉线**：脚本会直接以「真机已断开连接」失败，不会再空转 400 轮。
