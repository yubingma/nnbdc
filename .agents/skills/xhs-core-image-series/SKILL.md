# 词核心图系列短视频（小红书 9:16）

## 0. 一句话定位

> 一集一个单词，讲透**一个意象**：先抛出几个看似毫不相干的释义制造冲突，再亮出它们共同的核心意象，
> 最后用**从中心生长出去的箭头**逐条指到各释义，并念成「什么现象 → 就是哪个意思」的完整句子。

它不是「单词卡」，而是**词义解析**：卖点是"这几个意思居然是一回事"这个认知冲击，不靠谐音梗。

## 1. 与既有技能的分工

| 技能 | 干什么 | 关系 |
|---|---|---|
| `xhs-video-pipeline` | 用通义万相 + ffmpeg 包装，把 **App 录屏/界面截图**做成营销片 | 那条链路面向"推 App"，素材是真实功能演示 |
| **本技能** | 把 **word_core_image 数据**做成知识内容片 | 面向"养号涨粉"，画面全部本地渲染 |

两者共用同一套底层认知：DashScope Key 在 `~/.zprofile` 的 `dashscope_api_key`；
配音都是通义 TTS；输出都是 1080×1920 竖屏。**底层管道已抽成 `tools/xhs_video_pipeline/xhs_common.py`，两边都 import 它，不要各写一套。**

## 2. 内容资产从哪来（这是本系列的弹药库）

数据全在 `word_core_image` 表（**标准叫法「词核心图」**，见 `doc/glossary.md` 4.7）：

| 字段 | 内容 |
|---|---|
| `core_image` | 核心意象，一句话，如 spring =「蓄势猛然向外迸发」 |
| `schema_desc` | 展开解释 |
| `topology_json` | `{core_image, schema_desc, branches[]}`，**branches 里每条含 `pos` / `meaning` / `relation` / `desc`** |
| `image_prompt` / `image_url` / `image_status` | 生图提示词与成品图 |
| `is_applicable` / `not_applicable_reason` | 是否适合做意象解析（单词只有单一具体义时会被判为不适用） |

`branches[].relation` 就是**花字与配音的原料**（如「受压蓄力后，回弹复位」）。

规模（2026-10 实测，会变，**用前实时查库，别引用旧数字**）：

- 总记录约 **19784** 条，其中 `is_applicable=true` 且出图成功 **3690** 个词
- 其中 **2188 个是考研词**，平均 **4.4** 个释义分支（最多的 `back` 有 18 条）
- 产地：DeepSeek 做认知分析 + 豆包 Seedream 出图；图 512×512，白底黑线简笔画

**取图**（数据库只存相对路径，图在生产服务器）：

```bash
python3 tools/xhs_video_pipeline/fetch_core_images.py spring charge
python3 tools/xhs_video_pipeline/fetch_core_images.py --episode tools/xhs_video_pipeline/episodes/ci01_spring.json
```

脚本只读本地 `bdc` 库 + scp 拉远程文件，落在 `tmp/xhs_video_pipeline/core_images/`。
**白底黑线的图会被自动反相成「透明底 + 白线」**再叠到深色画布上（`xhs_common.load_line_art`）。

## 3. 一集长什么样

四段结构，总长约 **25~30 秒**（时长由配音实际长度反推，见 §6）：

| 段 | 干什么 | 画面 |
|---|---|---|
| `hook` | **同时充当封面**：抛出几个毫不相干的释义制造冲突 + 提问 | **单词 + 音标 + 核心意象图 + 三个释义卡，第 0 帧就全都在**，只有提问行是后出的节拍 |
| `core` | **念出「核心意象」这四个字**并给出那一个意象 | 词核心图放大淡入，下方「核心意象」小标 + 意象大字 |
| `radiate` | 逐条把释义接成完整句 | 图缩到中上，释义卡散布四周，**箭头从中心逐条生长指过去**；关联文字**逐字高亮**，念到「就是X」时释义整块点亮 |
| `outro` | 金句（可两行）+ **互动提问** + 引导胶囊 | 居中大字，**只上屏、不配音**，见 §10 |

> ⚠️ **小红书封面默认取视频第一帧。** 所以片头不能是"元素陆续飞入"的空场——
> 那样第 0 帧是一片空白，封面就废了。凡是必须出现在封面上的元素
> （单词拼写、音标、核心意象图、释义卡）都要**在第 0 帧就是全不透明**：
> 用 `ImageLayer(..., fade_in=False, scale_from=0.93)` 做"不淡入、只缓慢缩放"，
> 文字层则把 `start` 设成负值（如 `-1.0`）让它一开始就到位。
> 全片只留**一个**后出的节拍（提问行在 1.3s 出现）即可。

## 4. 单集脚本 JSON

放在 `tools/xhs_video_pipeline/episodes/`，命名 `ci<序号>_<单词>.json`：

```json
{
  "episode": "CI01", "series": "词核心图", "position": "01",
  "slogan": "一个词 · 一个意象", "accent": "#6EE7B7",
  "word": "spring", "phonetic": "sprɪŋ",
  "core_art": "core_37865.jpeg", "core_text": "蓄势猛然向外迸发",
  "core_sub": "spring 只有这一个意象",
  "voice": "Pip", "voice_model": "qwen3-tts-flash", "music": "burst",
  "segments": [
    { "type": "hook", "word_intro": true, "cards": ["春天", "弹簧", "泉水"],
      "line": "这三个意思，有关系吗？", "say": "春天、弹簧、泉水。有什么关系？" },
    { "type": "core", "word_intro": true, "say": "核心意象：蓄势，猛然向外迸发。" },
    { "type": "radiate", "items": [
        { "meaning": "弹簧", "relation": "受压蓄力后，回弹复位" } ] },
    { "type": "outro",
      "line": "一词多义\n记住一个意象就够了",
      "ask": "哪个一词多义把你折磨过？",
      "cta": "告诉我 · 下集就讲它" }
  ]
}
```

要点：

- **`dur` 和 `reveal` 不要手写**，留空即按配音实际时长自动反推。只在需要干预节奏时才显式指定。
- `line` 支持 `\n` 手动断行（金句用），会按最长一行自动缩字号。
- `word_intro: true` 表示该段开头先读一遍单词，中文讲解等它读完再进来。
- 配音音色是**单集可配**的（`voice` / `voice_model` / `voice_instructions`），不写死。
- `radiate` 的 `items` **不写 `say`**：配音由 `relation` 和 `meaning` 自动拼成两段
  （`"{relation}，"` 与 `"就是{meaning}。"`），见 §7 第 10 条。

### 5.1 交付到相册（便于手机端发布）

> **只导「刚做出来的那一集」。已发布过的旧集一律不要重导。**
>
> 用户的原话：「以后只需要导入最新的一个视频，以前的就不用管，因为我都已经在小红书发布了。
> 重新导没有意义。」
>
> 原因很实在：**Photos 的脚本删除在本机不通**（见下），而同一个文件名反复重录必然产生同名副本，
> 清不掉、只能手动删。所以**修订一条已经发布过的集数时，只出片到 `design/ui/video/`，
> 绝对不要碰相册**——导进去只会给用户添清理负担。
>
> 操作上：新集首发出片后（且用户要求导入时）跑一次 `to_photos.py`；此后这条集数的任何改版
> 都只落盘、不导入。


```bash
python3 tools/xhs_video_pipeline/to_photos.py            # 导入最新一条成片
python3 tools/xhs_video_pipeline/to_photos.py a.mp4 b.mp4
python3 tools/xhs_video_pipeline/to_photos.py --list     # 只看看会导入什么
```

用 AppleScript 把成片导入 macOS「照片」，统一归到专辑 **「小红书 · 词核心图」**，不混进照片流。
**开 iCloud 照片的话会自动同步到手机相册**，直接在手机上发小红书，不用 AirDrop 或传微信。

两个注意点：

- **Photos 不去重**：同一个文件导入两次会出现两条。而且 **AppleScript 的 `delete` 在本机实测会报
  `-10000 AppleEvent handler failed`**——读相册、建专辑、导入都正常，唯独删除不行（按 `media item i`、
  按 `id`、先收集再删三种写法都试过，全部失败）。所以**脚本没法帮你清旧版本**：
  重录之后要么在「照片」App 里手动删掉旧的那条，要么就别重复导。
  出片前先想清楚要不要导，比事后清理省事。
- 首次调用会申请「自动化」权限（系统设置 → 隐私与安全性 → 自动化），拒绝过就导不进去。

## 6. 配音与配乐

- 模型：`qwen3-tts-flash`（默认）或 `qwen3-tts-instruct-flash`（**支持 `instructions` 用文字指令控制语气**，可与音色叠加）。
- **通义 TTS 是非确定性的：同一句话多次合成，长度每次都不一样。** 实测片头一句在
  **3.68 / 3.84 / 4.80 / 5.44 秒** 之间波动，收尾一句在 2.96 / 3.60 / 4.72 秒之间波动。
  三个后果必须记住：
  1. 时长只能**先合成、后推算**（本管线已经是这个顺序），任何"按字数估时长"的做法都不成立；
  2. **`tmp/xhs_video_pipeline/<集号>/audio/` 这份缓存不能清**——清了重新合成，成片长度就会变，
     连带进度条、箭头生长时机、逐字高亮全部跟着变。它是这条成片的时间基准，不是可丢弃的中间产物；
  3. 一集要**一次跑完**，别在中间反复重跑。
- 计费 **0.8 元/万字符**，按输入文本字符数计（[官方文档](https://help.aliyun.com/zh/model-studio/qwen3-tts-flash)）。一集几十个字符，成本可忽略。
- **缓存键必须含「文案 + 音色 + 模型 + 语气指令」**。只按文案做键的话，换音色会静默复用旧音频，看起来像没生效。
- 常用音色（全部实测可用）：

| voice | 音色名 | 特点 |
|---|---|---|
| `Cherry` | 芊悦 | 阳光亲切（默认基准） |
| `Momo` | 茉兔 | 撒娇搞怪 |
| `Pip` | 顽屁小孩 | 调皮捣蛋，小新既视感（本系列当前采用） |
| `Ryan` | 甜茶 | 节奏拉满，戏感强 |
| `Vivian` | 十三 | 拽拽的小暴躁 |
| `Peter` | 李彼得 | 天津相声捧哏 |

需要横向挑选音色时，做一条**试听片**（同一句话用各候选各读一遍、串成一条视频）让用户自己听——
**不要凭音色名的描述替用户下结论**。

### 6.1 配乐：默认关掉

**当前默认不配乐。** 实测结论：30 秒左右的知识短视频，**垫乐完全去掉反而更干净**——
人声和箭头的敲击声清楚了，也不再有"跟内容抢注意力"的风险。
成片音频只剩三层：**人声、箭头音效（气泡音）、段落音效**。

想要垫乐就在单集脚本里加一行 `"music": "burst"`（见下方档案表），代码与能力都还在。
下面是踩过的坑，将来真要用垫乐时照这个来。

**判断"有没有垫乐"的客观方法**：看整条片子音频包络的**低分位**。
无垫乐时 1%/5%/10% 分位都是 0.00000；有垫乐时下限会被垫乐托住，低分位明显大于零。

---

### 6.2 垫乐（可选）要跟着核心意象走

BGM 不是"随便垫一条"，它是**潜意识里强化意象的那一层**。垫乐由 `xhs_common.synth_bgm` 本地合成，
零成本、可参数化，用四个抓手对应意象的动力学特征：

| 参数 | 取值 | 听感 | 对应意象 |
|---|---|---|---|
| `motion` | `rise` / `fall` / `cycle` | 音高上行 / 下行 / 往复 | 迸发 / 压入 / 旋转 |
| `scale` | `major` / `minor` | 明亮 / 低沉 | 舒展 / 沉重 |
| `weight` | 0~1 | 底鼓更沉更密 + 低频托底 | 有重量、有压力 |
| `brightness` | 0~1 | 泛音多少、沙锤轻重 | 清亮 / 闷厚 |
| `bpm` | 60~120 | 速度 | 急切 / 从容 |

内置档案（`MUSIC_PRESETS`）：`burst` `load` `spin` `cut` `soar` `press`。
单集脚本里写 `"music": "load"`，也可以直接给参数字典。

**防"听着心烦"的四条铁律**（这是一次真实返工换来的：初版被听出"重复感明显"）：

1. **和弦每小节换一次，不要每拍换一次。** 初版每拍换和弦，104 BPM 下一拍 0.58 秒，
   四个和弦轮一遍只有 **2.3 秒**，37 秒的片子里重复 16 遍——这是"心烦"的主因。
2. **和弦进行要长过整条成片。** 现在每种调式都是 **16 小节**：104 BPM 下 36.9 秒、
   82 BPM 下 46.8 秒。判断标准不是"我数了数有 16 个"，而是**实测**：把每小节的和声内容
   折成 12 维音级向量（chroma），做自相关，看多短的周期相关度会超过 0.5。现在是**测不出周期**。
3. **和弦垫必须是持续音，不能是"拨一下就衰减"的短音。** 那种哒-哒-哒的机械感大半来自它。
4. **织体分层推进：垫底 → 加低音 → 加琶音沙锤 → 加花。**

> ⚠️ 第 4 条有个陷阱：**"加了层"不等于"听得出来"。** 初版把低音/琶音/沙锤逐层加上去，
> 但实测每层响度是 0.125 → 0.130 → 0.123 → 0.132，**完全是平的**——因为响度的主体是垫音，
> 后加的层全被盖住了。真正有效的做法是**让开头更空**：垫音本身逐层加音（根音 → 加三度 →
> 加五度 → 加泛音），底鼓也从第 2 层才进。改完实测 0.093 → 0.119 → 0.122 → 0.131（+41%），
> charge 0.069 → 0.092（+33%）。
>
> **教训：凡是"渐强 / 推进 / 层次"这类声称，都要拿数字验一遍。测不出来就是自我安慰。**

**⚠️ 嗡鸣不来自"低音"，来自"持续不断的纯音"。** 这条踩过一次，方向还判断反了：

用户反馈「敲击轻快的声音舒服，那个缓慢低沉的声音去掉」。我先去掉了两条 55 Hz 的层，
结果用户回「你弄反了，我要的是敲击声，不是这种低沉的嗡嗡声」——**因为底鼓恰恰就是他喜欢的敲击声，
而我当时还打算怀疑底鼓**。

真正的嗡鸣源是**和弦垫**：三条正弦音快起慢落、跨整小节挂着，音高根本不算低（110~165 Hz），
但**持续不断的纯音听感上就是嗡鸣**，跟音高没关系。

**结论：垫乐要用拨奏（快起快落），不要用持续音。**

判断标准可以量化——比**小节头 0.25 秒与小节尾 0.25 秒的响度比**：

| 形态 | 头尾响度比 | 听感 |
|---|---|---|
| 持续音垫 | ≈ 1 | 嗡鸣 |
| 拨奏（衰减 2.4/s） | 2.0 ~ 4.5 | 还是糊 |
| **拨奏（衰减 3.8/s）** | **7.1 / 23.7** | 清晰的敲击 |

衰减太慢时，每小节的第二记还没落下去、第一记的余音还在，会糊成一片——**光"改成拨奏"不够，
衰减要快到每一记都干净收住**。

**低频层已被用户否掉，不要再加回来。** 初版有两条 55 Hz 的层——「全程不断的低频托底」和
「每小节一记、衰减近 3 秒的低音根音」。用户听完的反馈是「敲击轻快的声音舒服，那个缓慢低沉的
声音可以去掉了」。**两条都删了**，理由不是"低频不好"，而是：

- 它们是**没有节奏的持续低音**，在一段 30~37 秒的片子里听起来就是嗡鸣，而不是音乐；
- 真正提供重量感的是**底鼓**（有明确起落），不需要再叠一层持续低音。

**诊断手法（下次判断低频来自谁，照这个来）**：`_LAYERS_PER_STAGE` 决定了第 0 层只有垫音、没有底鼓，
所以直接比第 0 层与第 1 层的 <80Hz 能量占比，就能把「垫音的低频」和「底鼓的低频」分开。
实测垫音的第 0 层 **<80Hz 占比 0.0%**，全部低频都来自底鼓。

**实测差异**（同一模板的两集，只换了档案）：

| 集 | 档案 | 频谱重心 | 低频占比 | 高频占比 |
|---|---|---|---|---|
| spring | `burst` | 775 Hz | 40.1% | 4.6% |
| charge | `load` | 383 Hz | 50.3% | 1.7% |

**注意**：垫乐只负责衬底，音量始终压在讲解之下（`bgm_gain`，默认 0.30）。
它一旦抢戏，观众会先注意到音乐而不是内容——那不是我们要的。

**批量时**：档案名可以由 `core_image` 文本交给大模型判定（和"释义分支"同一条批处理链路），
不需要人工为 2188 个词各挑一次。

## 7. 排版与几何约束（这些都是踩过的坑）

1. **首帧必须是完整封面构图**（详见 §3 的警示）：小红书封面取第一帧，元素若在陆续飞入，
   封面就是一片空白。成片后**务必抽第 0 帧**确认：

   ```bash
   ffmpeg -y -ss 0 -i design/ui/video/CI01_spring_core.mp4 -frames:v 1 -vf scale=430:-1 /tmp/cover.png
   ```

2. **音标必须用 `Arial Unicode MS`**（`xhs_common.FONT_IPA`）。Helvetica Neue / Avenir Next / Apple SD Gothic **都缺 `ɪ` `ˈ` `ɛ` `ɚ`**，会渲染成方框。
3. **单词发音首尾带静音**（有道的 spring 原始 1.95s，实际发声仅 0.88s），`fetch_word_audio` 会自动剪掉。不剪会把后面的中文讲解整段往后推。
4. **节点数决定布局，两套并存**：
   - **≤4 个节点**用 V 形（手工排定，箭头长度有保证）；
   - **≥5 个节点**改用**环形均布**，且环的圆心要比 V 形更低
     （`RING_CY = 944` 对 `HUB[1] = 648`）——沿用 V 形圆心时**顶部节点会直接压在单词词头上**，
     这是实际返工过的一次；环形下核心意象要缩小（`ART_BOX_MANY = 220`）、节点收窄（`NODE_MAX_W_MANY = 200`）；
   - 片头释义卡**超过 3 张**时同样要改成**每行最多 3 张的网格**，竖排到第 5 张就会压到进度条。
5. **为什么 V 形不能直接扩成同心环**：画布只有 1080 宽，核心意象占 300、释义卡占 256，
   同心环会让左右两条箭头**退化成零长度**。V 形正是为绕开这一点才手工排的。：画布只有 1080 宽，核心意象占 300、释义卡占 256，同心环会让左右两条箭头**退化成零长度**。当前 `_SLOTS` 写死 1~4 个节点的排布。
   - **这条视频舒服地放 3 个释义节点就是上限**，要更多就得缩小核心意象或收窄节点。
6. **箭头起止点要按「矩形出边」算**（`_rect_exit`），不能用固定像素间距，否则箭头会扎进图里或戳进卡片。
7. **中文断行优先在标点处断**（`wrap_cn`），逐字硬断会把词从中间劈开成「受压蓄力后，回 / 弹复位」。
8. **段循环里写 lambda 要防晚绑定**：`for s in segments:` 里的 `lambda: s["line"]` 会全部指向最后一段，
   表现为「片头显示的是片尾的金句」。用默认参数把值绑死。
9. **词核心图原图只有 512×512**，裁掉白边后约 410px。**不要强行放大到 1080**，会明显发虚；
   要更大的存在感得重新出图。
10. **音效要给足音量，短音效尤其**：`radiate` 段每个箭头长出去时各响一声 `bubble-pop.wav`
   （和箭头的起点、配音的开口**同一时刻**，给动作打拍子）。这个音效只有 **0.08 秒、峰值 -6.9dB**，
   按 0.42 的增益放进去几乎听不出来，要用 **1.0**。判断它有没有生效时注意：
   **箭头起点正好是单词/讲解开口的时刻，波形测量很容易把音效的包络误当成语音的起音**——
   要么挑一个前后没有语音的窗口，要么直接对比不同增益下同一位置的包络有没有成比例变化。
11. **音轨要按用途打标签**（`kind`: `voice` / `sfx` / `word`）：配音重叠断言只能比 `voice`。
    靠文件后缀判断是不行的——`bubble-pop.wav` 也是 `.wav`，会被当成"两句人声叠在一起"而误报。
12. **小红书播放页底部会盖住画面**：左下是标题正文、右下是互动按钮列。
   底部进度条要上移到约 **0.84H**、右端收到约 **0.84W** 之前。这个安全区是推算值，**建议真发一条（仅自己可见）核对**。

### 7.1 一个案例：bear 的「熊」该不该收进来

`bear` 的动词族（承受 / 支撑 / 携带 / 结果 / 具有）都从「**扛住重量，带着走**」引申出来。
但 `bear` 作「熊」讲，词源上来自古英语 *bera*「棕色的那个」，与动词的 *beran*「携带」**是两个不同的词**，
属于同形异源，按纯词源标准应当排除。

**产品决定：收进来。** 用户的理由是「我们的目的是帮用户记忆，以词源为基础，但不完全严谨追溯词源」，
而且「熊要承受自己巨大的体重、要忍受寒冬」这个联想本身就成立、比词源更好记。

所以核心意象被放宽成能同时罩住两者的 **「扛住重量，带着走」**，`熊` 作为第一个节点
（关系写作「一辈子扛着自己体重的野兽」）——**既当钩子又当记忆点**。

**这是一个有意识的取舍，不是疏漏**：代价是这套方法的严谨性打了折（观众可能以为"熊"也是推导出来的），
换来的是这一集最好记的一个意思。换别的词时若遇到类似情形，按同一原则处理——
**先问"这个联想能不能帮人记住"，再问"词源上站不站得住"**，但要在脚本里当作有意为之。

## 9. 已知限制

- 一集只讲 3 个释义，而一个词常有 4~18 条分支，**必须挑最反直觉的三个**。
- 视觉节奏是「一句一停」，中文配音偏慢时整条会到 30 秒。要压缩就先减条目间的留白（`GAP`），别先砍文案。
- 批量生产还差两步自动化：**从库里按「释义分支数 × 考试词书覆盖度」自动挑词**，以及**把 `relation` 改写成「现象 → 就是 → 释义」的完整句**（这句式可以直接交给大模型批量做）。

## 10. 互动设计（收尾的提问）

**这是一条经验证的结论，不是可选项。** 实测数据：点赞率不错但**几乎没有评论**。

原因不是内容不好，而是**视频太完整了**——三个释义讲完、意象揭晓、金句收尾，观众看完只有"哦，懂了"，
没有任何未闭合的东西需要表达。点赞是情绪认可（零成本），评论必须有话可说。

**做法：收尾把「下集预告」换成「向观众征集选题」。**

> 哪个一词多义把你折磨过？告诉我，下集就讲它。

这条比"下集讲 shock 还是 pack，打 1 或 2"更好，因为：

1. 评论成本一样低（打一个词就行），但观众的答案**本身就成了下集素材**；
2. 形成「评论 → 下集内容 → 再引评论」的正循环，下集可以直接说「上集有位朋友提到了 X」；
3. 选题从"我拍脑袋定"变成"真实需求"，长期看内容命中率更高。

**实现要点：**

- 收尾有 **三块内容**：金句（`line`）、提问（`ask`）、引导（`cta`）。
- **不配音、也不逐条显现、也不做入场动画**：整屏在 `OUTRO_AT = 0.00` 一次性出现，
  背后只留 `OUTRO_FADE = 0.15` 秒的软化（避免硬切突兀），总长 `OUTRO_DUR = 1.20` 秒。
  想多留点阅读时间就调 `OUTRO_DUR` 这一个数。

> ⚠️ **"同时开始"不等于"同时出现"。** 这里返工过一次：三块内容虽然都把 `start` 设成同一时刻，
> 但**各自还带着 0.55~0.6 秒的淡入 + 上浮**，于是前 0.6 秒画面仍在动，用户直接问
> 「为什么最后一屏还是延续了一小段时间？只有一屏文字就应该是瞬间」。
> 说"一次性出现"时，要连**入场动画**一起去掉——`dur` 和 `rise` 都得归零，
> 光把 `start` 对齐是不够的。

这两条都是用户实测后定的，而且**两次都是同一个毛病的两种表现——让画面等声音/等动画**：

| 版本 | 收尾时长 | 问题 |
|---|---|---|
| 逐句配音 | 9.5~10.8 秒 | 屏幕上写着的字还念一遍，纯拖时长 |
| 去掉配音、逐条显现 | 4.5 秒 | 逐条蹦出来又白拖了 2.8 秒 |
| 一次性出现（但带淡入上浮） | 3.0 秒 | 前 0.6 秒画面仍在动，"瞬现"没做彻底 |
| **一次性出现 + 无入场动画** | **2.0 秒** | 静止画面主观上比实际更长 |
| **再压到 1.2 秒** | **1.2 秒** | 用户拍板：宁可牺牲一点阅读时间也要压完播 |

三条片子的收尾从 ~10 秒一路压到 **1.2 秒**，**成片整体短了约 8~10 秒**
（spring 37.0→27.4、charge 30.1→21.5、accord 31.6→23.3）。

- 所以 `outro` **既没有 `say` 字段、也没有任何音效**（`SFX_BY_TYPE` 里没有 `outro` 这一项），
  也不要再加回来——那一屏只有字，多一记盖章声纯属多余。`plan()` 里这一段不合成任何音频。

> ⚠️ **收尾变全静音后暴露了一个容器层的坑：音轨会比视频短一截。**
> `amix` 用 `duration=longest`，只混到最后一条音频结束为止；结尾几秒本来就没声音时，
> 音轨就断在那里（实测 charge 音轨 19.88s vs 视频 22.33s）。之前有盖章声和配音撑着，
> 正好把这个缺陷盖住了。**修法是混音链末尾加 `apad`**（补静音到无限，再由 `-t` 统一裁齐）。
> 收工前核一下两条流的长度是否相等：
>
> ```bash
> ffprobe -v error -select_streams v:0 -show_entries stream=duration -of default=nw=1:nk=1 x.mp4
> ffprobe -v error -select_streams a:0 -show_entries stream=duration -of default=nw=1:nk=1 x.mp4
> ```
- **替换而不是叠加**：原来那句「一天一个词，关注追更」让位给引导语。

> **通用原则：凡是屏幕上已经写着的字，都不要用配音念一遍；凡是观众一眼能看完的一屏，
> 都不要拆成逐条显现。** 配音只承载屏幕承载不了的信息（单词发音、引申逻辑的讲解），
> 动画只在有信息增量时才做（比如箭头从中心长出、释义逐条指过去——那里有真实的引申关系）。

**发布侧同样关键（不做的话视频里问了也白问）：**

- 发完**立刻自己置顶一条评论**。从 0 条评论到 1 条，比从 1 条到 10 条难得多，空评论区会劝退所有人。
  置顶内容最好**示范一个答案**（「我先来：我以前以为 charge 只有充电的意思」），而不是只喊"大家来评论"；
- 前 30 分钟逐条回复，平台看重早期互动密度，回复也会把评论顶上去。
